# Unity 6 import verification (Phase 3)

> **Re-export before you import (2026-10-26).** Every textured GLB and Unity package exported before commit "fix(export): glTF texture V
> orientation" showed its texture **mirrored vertically** in glTF-conforming readers, Unity included (the writer left V pointing up; glTF
> counts from the top). If you already imported a package and the paint looked scrambled, that was the cause, not Unity. Re-export from the
> Studio (or re-run the lab notebook) and import the new package. The fix was verified by importing the GLB into Blender
> (`tests/test_blender_export.py`), not by Unity.

**Status in this repository: BLOCKED.** No Unity editor is available where this project is built, so nothing has been
imported into Unity. The exported package is *integrity-verified* (checksums, glTF structure, Khronos validator) – that is
**not** an import verification, and `Metadata/asset.json` keeps `"unity_import_verified": false`.

What exists and is tested here: the verifier script `Editor/AroUnityVerifier.cs` (in every package) which parses with
tree-sitter (`tests/test_unity_scripts.py`) but **has never been compiled or executed in Unity**; the expectations file
`Metadata/unity_expectations.json` (computed from the scene, independent of the glTF); and the evidence reader
`aro_studio/verification/evidence.py`, which refuses to report PASS unless every required check passed in a Unity 6 editor.

## Requirements

* Unity **6** (6000.x) with the Universal 3D (URP) or Built-in template. Unity Personal is free; no paid asset is required.
* Package **glTFast** (`com.unity.cloud.gltfast`) installed in the project (Package Manager → *Add package by name*).
  Record the exact versions in the evidence (the verifier does this).
* A Unity package generated by the Studio for the asset under test (`Exports → Unity 6 package`, or the acceptance run).

## Steps

```bash
# 1. produce the package and unzip it into the project
python scripts/run_acceptance.py            # writes the package; or export from the UI
unzip ARO-TITAN-480-Unity-*.zip -d MyUnityProject/Assets/

# 2. let Unity import + compile it once (opens the project, so you can see Console errors)

# 3. batch-mode verification (omit -nographics if you want screenshots)
"/path/to/Unity" -batchmode -projectPath MyUnityProject \
  -executeMethod ARO.Studio.Editor.AroUnityVerifier.Run \
  -aroPackage Assets/ARO-TITAN-480-Unity \
  -aroReport "$PWD/docs/acceptance/evidence/unity/unity-verification.json" \
  -aroShots  "$PWD/docs/acceptance/evidence/unity/screenshots" \
  -logFile "$PWD/docs/acceptance/evidence/unity/unity-editor.log" -quit
echo "exit code $?"        # 0 PASS · 1 FAIL · 2 PARTIAL
```

If the package scripts do not compile, Unity never runs the method and no report is written – that is a **FAIL** (keep the
`unity-editor.log`). Fix the C# (`aro_studio/export/unity_templates.py`, `unity_verifier.py`), never loosen the check.

## What the verifier checks

| Requirement | Check |
|---|---|
| Unity version | editor reports `6000.x` |
| Import errors | no Error/Exception log lines during import and prefab build |
| Scale | world bounds size of LOD0 == `unity_expectations.json` extents (±0.01 m) |
| Orientation | world bounds == expected box with X mirrored: +Y up, +Z forward, ground at Y = 0, root scale 1 |
| Handedness / coordinate conversion | every off-centre part sits at the X-mirrored position (left stays left); the un-mirrored match count is recorded. If no part is off-centre the check is `NOT_TESTABLE` ⇒ overall PARTIAL |
| Materials / textures | no null material, no error/unsupported shader, expected materials present, texture bindings counted |
| LOD hierarchy and switching | LODGroup level count, per-level triangle counts and transition heights match `lods.json`; renderers disjoint; triangles strictly decrease; `LODUtility.CalculateVisualizationData` at 4–320 m starts at LOD0, never returns to a finer level and changes |
| Collision | each collider exists with the right component type, dimensions and (mirrored) position; convex mesh colliders ≤ 255 triangles with a mesh |
| Hierarchy and names | every expected part present by exact name; `Collision` group; no duplicate sibling names |
| Scripts / references | no missing scripts, no broken object references on the prefab, `AroVehicleDescriptor` attached |
| Prefab builder | `ARO ▸ Build Vehicle Prefab` runs from the GLB and writes the prefab |

## Recording the result

`unity-verification.json` (schema 1) holds: Unity version, render pipeline, glTFast version, package path, sha256 of the
package `checksums.sha256`, every check with PASS / FAIL / NOT_TESTABLE and detail, Console errors/warnings, screenshots and
the list of things *not verified* (e.g. screenshots in `-nographics`). Commit it with the screenshots and the editor log. The
acceptance report then reads it (stage 22 and component 5):

| Evidence | Status |
|---|---|
| no file | BLOCKED |
| any required check FAIL, non-6000.x editor, Console errors, unreadable file | FAIL |
| everything passed but something `NOT_TESTABLE` / not verified | PARTIAL |
| every required check present and PASS | PASS |

The reader cannot detect a hand-edited file – reviewers must read the log and screenshots.

## Known limits (stated up front)

* The expected X-mirror is glTFast's documented behaviour; the verifier measures rather than assumes it and reports both
  match counts, so a different convention shows up as a FAIL with numbers.
* Runtime LOD selection is verified through the Editor's own LOD visualisation API, not a running player build.
* Wheel colliders / vehicle physics components (Unity WheelCollider, ARO game scripts) are out of scope for this package.
